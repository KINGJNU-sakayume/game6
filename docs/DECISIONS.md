# 구현 결정 기록

설계 문서(`docs/design.md`)에 없거나, 구현 중 바꾼 사항을 적는다. 형식: 날짜 · 무엇을 · 왜.

## 2026-09-30

- **설계 v1.1 확정.** 사용자 요청("먼저 비판적으로 검토해서 수정")에 따라 v1.0을 검토하고 고쳤다. 근거는 `docs/REVIEW.md`.
- **계층 경계는 ESLint 대신 테스트로 강제.** `tests/arch.test.ts`가 `src/core`, `src/content`, `src/ui`, `src/sim`의 import 문을 검사한다. 도구 사슬을 줄이고 같은 규칙을 지키기 위해서다.
- **React 18.3 + 클래식 JSX.** 배포용 단일 HTML에서 React를 cdnjs UMD로 불러오기 위해 React 19 대신 18.3.1을 쓴다.
- **약물 금기는 전신 반응으로 판정한다.** v1.1은 "대상 중증도를 floor(d1/2) 회복"이었다. 구현해 보니 피해가 작은 약은 금기여도 거의 손해가 없었고, 다른 질병을 대상으로 골라 금기를 피할 수 있었다. 약은 환자 몸 전체에 들어가므로 투여 순간 살아 있는 모든 질병에 대해 판정하고, 반응은 `max(6, floor(d1/2))` 회복 + 악화 1로 바꿨다. 처치는 피해가 닿는 대상에게만 반응한다. design §4.4에 반영.
- **지도 노드 종류는 허용된 종류 안에서 가중 추첨한다.** "추첨 후 제약 위반이면 다시, 실패하면 전투"는 형제 노드가 둘 다 전투가 되어 "자식은 서로 달라야 한다" 제약을 어겼다(시드 500 테스트에서 발견). 제약을 어기지 않는 종류만 모아 추첨하고, 하나도 없을 때만 전투로 둔다.
- **두 질병 인카운터는 중증도 60%, 공격 60%.** v1.1의 "중증도 65%"만으로는 두 질병이 같은 턴에 때려 단일 인카운터보다 크게 어려웠다(탐욕 봇 활력 손실이 두 배 이상). `EncounterDef.enemies[].atkPct`를 추가했다.
- **1차 밸런스 조정.** 탐욕 봇 기준 첫 구현은 승률 0%였다(질병이 너무 약한 대신 두 질병 조합과 DKA가 벽). 질병 수치를 다시 잡고(design §5.5 표), 봇이 적응증 없는 카드를 과대평가하던 문제를 고쳤다. 결과는 `PROGRESS.md`.
- **카드 가치 예산 경고 18건은 두었다.** `validateContent`의 예산 계산은 피해·안정화 위주라 뽑기·진단·정리 같은 유틸리티 카드를 잘 재지 못한다. 오류가 아니라 경고로 남기고, 실제 조정은 시뮬레이터 결과로 판단한다.
- **전투를 끝내는 카드의 지속 부작용도 덱에 남는다.** 마지막 일격이 된 아미오다론의 폐독성 카드가 사라지던 문제. 전투 종료 시 대기 중인 부작용 명령에서 지속형만 처리한다.
- **사망 원인 표기.** 부작용이나 상태로 죽으면 `se:<카드ID>`, `status:<상태ID>`로 기록해 종료 화면에 "치료 부작용 — 오심"처럼 보인다.
- **UI는 1280×720 무대 하나, 밝은 테마 하나.** 병원 서식·모니터라는 한 가지 시각 세계로 고정한 디자인이라 다크 모드를 두지 않는다. 배경과 모든 색을 명시해 어느 호스트 바탕에서도 같게 보인다.
- **효과음은 WebAudio 합성.** 파일 없이 종이·경보·도장 소리를 만든다. 자동 재생 정책 때문에 첫 입력 뒤에만 소리를 내고, 설정에서 끌 수 있다.
- **배포 페이지의 React는 cdnjs, 실패하면 jsdelivr.** design §3.11은 cdnjs만 적었다. 한 곳이 막혀도 판이 열리도록 같은 버전 파일을 대체 경로로 둔다. 둘 다 막히면 안내 문구를 띄운다.
- **디버그 패널은 만들지 않았다.** 대신 `scripts/screenshots.ts`가 탐욕 봇으로 각 단계(전투, 보상, 상점, 당직실, 이벤트, 보스 유물, 종료)의 상태를 만들어 `window.claude.hot.data`로 주입하고, `scripts/ui-smoke.ts`가 실제 클릭으로 한 판을 진행한다. 아티팩트에서는 쿼리 문자열이 전달되지 않아 `?debug=1`을 쓸 수도 없다.
- **브라우저 검사 스크립트는 테스트 묶음 밖에 둔다.** 개발 서버와 Chromium이 필요해서다. 이 작업 환경에서는 CDN이 막혀 있어 검사 중 React UMD를 `node_modules`의 같은 버전 파일로 대신 주고, 글꼴은 Node 쪽에서 받아 넘긴다(브라우저가 프록시 인증서를 모른다).
- **CI(`ci.yml`)와 배포(`pages.yml`)를 나눈다.** 처음에는 한 워크플로에 배포 작업까지 넣었는데, 첫 배포가 `github-pages` 환경의 브랜치 보호 규칙(저장소 설정) 때문에 거부되면서 코드 검사 배지까지 빨갛게 됐다. 배포는 CI가 끝난 뒤 `workflow_run`으로 따로 돌고, 기본 브랜치의 push에서 CI가 통과한 경우에만 그 커밋(`head_sha`)을 배포한다. Pages 소스가 "GitHub Actions"가 아니면 실패 대신 안내를 남기고 건너뛴다. 저장소의 첫 브랜치가 기본 브랜치라 브랜치 이름을 적지 않고 `github.event.repository.default_branch`와 비교한다. 환경 보호 규칙은 저장소 보안 설정이라 워크플로에서 우회하지 않고, README에 허용 방법을 적었다.
- **CI가 찾은 UI 버그: 손패 확대 흔들림.** 카드 아래쪽 가장자리를 가리키면 확대된 카드가 커서 밖으로 올라가 확대가 풀리고, 내려오면 다시 확대되기를 반복했다. 커서 인식을 카드가 아니라 슬롯에 두고, 확대된 동안 원래 자리까지 인식 영역을 남긴다. 클릭 연기 검사가 이 흔들림을 확인한다.
- **브라우저 검사 스크립트는 실행기를 고른다** (`scripts/browser.ts`): `CHROME_PATH` → 이 작업 환경의 Playwright Chromium → 러너에 설치된 Google Chrome. 브라우저를 따로 내려받지 않는다.
- **긴 퍼즈를 CI에 넣었다.** 무작위 봇 200판이 약 20초라 매번 돌린다. 넣자마자 `legalActions`가 예산이 모자란 돌발 상황 선택지를 합법으로 내놓던 버그(시드 fz-58)를 찾았다. 고치고 회귀 테스트를 더했다(`tests/unit/legal.test.ts`).
- **웹 빌드는 상대 경로(`base: "./"`).** GitHub Pages는 `https://<사용자>.github.io/<저장소>/` 하위 경로에 올라가기 때문이다.

## 2026-09-30 · v2.0 임상 결정 재설계

요청: 플레이어가 감별 진단과 자율적 판단을 하는 의사처럼 느끼게 한다. 설계 전체는 `docs/design.md` v2.0, 이전 판은 `docs/design-v1.1.md`에 보존.

**진단**
- **진단 포인트를 없앴다.** v1.1은 진단 카드가 포인트를 쌓아 일정 점수에서 자동으로 감별·확진했다. 피해를 쌓는 것과 구조가 같아 판단이 없었다. 이제 진단 카드는 "무엇을 볼지"를 고르는 결정이고, 소견이 가설의 신뢰도를 움직인다(design §2.1).
- **신뢰도는 점수 대신 말로 보인다**(배제·가능성 낮음·가능·의심·강력 의심). 내부 점수는 봇·툴팁에만 쓴다. 비교 규칙에서 "정상인데 특징 소견을 기대했음"은 최대 2만 깎는다. 정상 소견 하나로 가설을 지우면 비전형 환자를 설명할 수 없어서다.
- **비전형 소견 50%.** 첫 구현은 증거가 너무 깨끗해 봇의 첫 작업 진단 정확도가 100%였다. 감별 대상이 둘 이상인 문제의 절반은 한 경로가 비전형이다. 정답을 최대 2만 깎아 배제는 못 하게 검증기가 강제한다.
- **활력징후는 감별 대상끼리 같게.** 첫 구현에서 활력징후가 거의 모든 내원 양상의 답을 흘렸다(예: 쇼크 = 아나필락시스). 같은 내원 양상의 후보는 활력징후 소견을 공유한다. 대신 병력·진찰·검사에서 갈린다.
- **질병 부담은 내원 양상 단위.** 질병마다 최대 체력이 다르면 숫자만 보고 진단이 드러난다.
- **확진은 피해를 바꾸지 않는다.** v1.1의 표적 ×1.5는 "확진 = 공격력"이라 진단을 피해 수단으로 만들었다. 대신 플레이어가 고른 **작업 진단**의 1차 치료에 ×1.3. 틀린 작업 진단도 고를 수 있고, 그 대가는 무반응과 시간이다.
- **작업 진단 변경은 오더 1.** 무료면 매 턴 바꿔 보는 것이 최선이 되고, 너무 비싸면 틀린 판단을 고칠 수 없다.
- **치료 반응을 소견으로.** 무반응이 "틀렸다"는 가장 임상적인 신호라서다. 반납은 치료가 아니므로 반응을 남기지 않는다.
- **의도는 압박 종류로 보이되 숨기지 않는다.** 행동 이름은 확진 전까지 숨기지만, 환자가 어느 방향으로 얼마나 나빠질지는 보인다. 이것은 관찰 가능한 임상 징후이고, 숨기면 안정화 결정을 할 수 없다. 정보 무결성 테스트는 이 예외만 명시적으로 빼고 비교한다. 의도 패턴을 외워 진단하는 것은 위험으로 남긴다(PROGRESS "남은 위험").

**카드와 결정**
- **범용 결정 명령 `choose_option` 하나로 통일.** 병력·진찰·검사·영상·배양·재평가·협진·시술·킥커 약이 같은 창을 쓴다. 선택지 조건은 플레이어가 아는 것만(검증기가 강제).
- **고를 수 없는 선택지도 보여 주고 이유를 적는다.** 왜 못 하는지가 곧 정보다(결과 대기, 이미 봄, 오더 부족, 혈전이 의심될 때만 등).
- **가짜 결정을 막는다.** 처방집에서 맞는 것이 하나뿐이면 "처방하지 않음"(오더 반환 + 1장)을 붙인다. 선택지가 모두 막히면 결정을 열지 않는다.
- **약은 처방집으로.** v1.1은 약을 덱에 섞어 "이 환자에게 쓸모없는 약"이 가장 흔한 죽은 드로우였다. 약·결정적 시술은 처방집에 두고 투약 오더·시술 의뢰로 불러낸다. 처방집 선택은 정답을 쓰지 않고 작업 진단(표적) 또는 감별 목록(경험적 덮기)으로 고른다.
- **반납.** 손의 치료 카드를 턴당 1회, 오더 없이 돌려보내고 1장 뽑는다. 죽은 드로우의 남은 부분을 결정으로 바꾼다.
- **협진이 주는 도구는 비용을 그대로 낸다.** 처음에는 이번 턴 비용 0이었는데, 협진 한 장이 관문 보스(상부위장관 출혈)를 활력 손실 2.9로 만들었다. 정보·접근성과 오더 템포를 맞바꾸게 했다.
- **협진 진료과 순서는 특성 일치를 두 배로.** 분류만 맞는 과(외과)가 출혈 환자에게 소화기내과보다 먼저 나와 내시경을 못 받는 일이 있었다.
- **뇌경색의 혈전용해는 CT 없이도 고를 수 있다.** 처음에는 CT를 본 뒤에만 권고가 열려 봇 승률이 0%였다. 이제 위험 문구가 "CT로 출혈을 배제하지 않고 쓰면 출혈 합병증"을 알리고, 실제로 그렇게 하면 출혈 카드와 활력 −6. 결정이 조건 잠금보다 낫다.
- **시술 위험은 플레이어가 아는 근거로.** 이 시술이 듣는 가설의 신뢰도가 강력 의심이면 낮음, 의심이면 활력 −2, 그 아래면 활력 −5와 합병증 카드. "확인 후 시행"은 오더 1로 확인 검사를 먼저 한다.
- **단순 카드가 다수.** 결정을 여는 카드는 64장 중 24장(38%). 결정이 없는 카드에는 결정을 억지로 넣지 않았다.
- **DUR 시스템에 반납 +1을 붙였다.** 반납 횟수 조정자(`extraReturn`)를 쓰는 유물이 없었다. 약물 안전 빌드와 맞는 유물에 붙였다.

**보상**
- **3칸(일반·상황·특수).** 상황 칸은 이번 막 환자에게 듣는 처방집만, 쓸모에 비례. 무작위 약 보상이 "이번 막에 쓸 데 없는 약"을 주던 문제를 없앴다.
- **관문·보스 뒤 다음 병동 처방집 신청.** 2막 환자에게 듣는 약이 처방집에 없어 2막 초반에 무너지던 문제(봇 사망 원인 1위)를 막는다.
- **퇴원 요약에서만 정답 공개.** 전투 중에는 절대 보여 주지 않고, 끝난 뒤 작업 진단이 맞았는지 알려 준다. 실패가 가르치게 한다.

**밸런스 (판단 봇 기준)**
- 시작 처방집에 아스피린·헤파린을 더했다(흉통·다리 부종이 1막부터 나온다). 관문(상부위장관 출혈)은 다음 병동 처방집 신청으로 내시경을 얻으면 너무 쉬워져(전투당 활력 손실 2.7) 부담 110%·공격 140%로 올렸다(7.9). 폐렴의 공격을 낮추고(기침 10→8), 1막 ESBL 신우신염 비율을 25%→15%로. 너무 쉬운 인카운터(심방세동, 췌장염, DKA, 섬망/간성뇌증, 폐색전증, 인공호흡기 경보)에 부담·공격 배율을 올렸다.
- 저장 파일 형식을 3으로 올렸다. v1.1 저장은 규칙이 달라 이어 하지 않는다(타이틀에 "이어 하기"가 뜨지 않는다).
